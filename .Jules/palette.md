## 2025-03-05 - Client-side Copy Accessibility and Hook Cleanup
**Learning:** For client-side copy interactions (such as the ClipboardCopy hook), state updates must be announced politely to screen readers using a visually hidden `aria-live="polite"` element and dynamic `aria-label` updates. Caching the original `aria-label` on mount prevents state corruption from rapid successive clicks. Explicitly cleaning up dynamic DOM elements, removing event listeners, and restoring original elements' attributes on `destroyed()` avoids memory leaks and DOM state corruption.
**Action:** Always preserve the initial accessibility attributes on hook mount, use a dedicated, cleanable `aria-live` polite container for async/temporary state announcements, and perform comprehensive element, listener, and attribute cleanup in the `destroyed()` callback.
