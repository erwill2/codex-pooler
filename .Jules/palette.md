## 2026-07-31 - [Clipboard Copy Accessibility and State Restoration]
**Learning:** For client-side clipboard copy elements, updating text states can cause critical screen-reader accessibility issues if updates are not politely announced via a visually hidden `aria-live="polite"` element. Furthermore, dynamically modifying the button's `aria-label` attribute during active/copied states can corrupt the initial element state on rapid successive clicks if the original value is not properly cached on mount. Finally, dynamically injected DOM elements and attributes must be explicitly removed and restored in the Phoenix LiveView hook's `destroyed()` callback to prevent memory leaks and unexpected state leftovers.
**Action:** Always extract complex interactions like clipboard copying into dedicated standalone modules, cache original `aria-label` states on mount, append an `aria-live="polite"` region inside the element, and explicitly remove any injected event listeners, elements, or mutated attributes in `destroyed()`.
