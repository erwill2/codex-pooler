## 2026-07-29 - Client-side Clipboard Accessibility and Lifecycle Hooks
**Learning:** For client-side copy interactions, state updates must be announced politely to screen readers using a visually hidden `aria-live="polite"` element and dynamic `aria-label` updates. Caching the original `aria-label` on mount prevents state corruption from rapid successive clicks. In Phoenix LiveView, hooks that dynamically modify the DOM, register listeners, or inject hidden containers must explicitly clean up those resources, remove elements, and restore the original states in their `destroyed()` callback to prevent memory leaks and state drift.
**Action:** Always implement robust `mounted()` and `destroyed()` pairs for dynamic interactive elements, ensuring all DOM modifications are reversed and screen reader support is integrated via `aria-live` containers and cached/restored semantic label attributes.
