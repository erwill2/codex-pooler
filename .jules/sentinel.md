## 2026-11-05 - Open Redirect Return Path Bypass via Encoded Characters and Backslashes
**Vulnerability:** The session `user_return_to` path was validated against unsafe fragments using raw binary checks (`String.starts_with?` and `String.contains?`) without first URL-decoding the string. This allowed URL-encoded sequences (such as `/%2fevil.example` and `/%5cevil.example`) and backslashes (`/\evil.example`) to bypass validation. When the browser follows a redirect to `/\evil.example` or encoded forms, it normalizes `\` to `/` and treats `//evil.example` as a protocol-relative external URL, redirecting the user to an untrusted domain after login.
**Learning:** Checking for raw substring patterns (`"//"`, `"/\\"` or control characters) on raw URLs fails when parameters or paths contain percent-encoded representations. Modern browsers also normalize backslashes following the leading slash (`/\`) into forward slashes (`//`).
**Prevention:** Always decode paths using `URI.decode/1` prior to evaluating path constraints (`/`, `//`, `/\\`, or control character fragments) when validating redirect targets.
