## 2026-03-24 - [Stripped Default Security Headers via Phoenix Controller Custom Map Overrides]
**Vulnerability:** Invoking `Phoenix.Controller.put_secure_browser_headers/2` with a custom map (e.g., specifying only `"content-security-policy"`) completely overrides and strips all standard browser security headers (such as `x-frame-options`, `x-content-type-options`, `x-xss-protection`, etc.) from the response, rather than merging them with Phoenix's defaults.
**Learning:** Phoenix's standard `put_secure_browser_headers/2` uses the passed map directly to replace the existing headers. If standard protections are not explicitly included in the custom map, the application's browser responses will lack critical browser defenses, leading to missing header security vulnerabilities.
**Prevention:** When customizing dynamic secure browser headers like CSP, always explicitly define or merge the custom header map with standard default secure browser headers to ensure defense-in-depth protections remain active.
