## 2026-07-30 - Phoenix Secure Browser Headers Override Vulnerability
**Vulnerability:** When calling `Phoenix.Controller.put_secure_browser_headers/2` with a custom map (e.g., dynamic CSP custom configurations), the default security headers (like `x-frame-options`, `x-content-type-options`, etc.) are completely overridden rather than merged, which risks stripping default protections if they are not explicitly merged or specified in the map.
**Learning:** Phoenix's design of `put_secure_browser_headers/2` uses the supplied headers directly and merges them onto the connection. If the custom secure headers map only specifies `"content-security-policy"`, other default browser protections may be omitted or skipped, depending on Phoenix's implementation and standard overrides.
**Prevention:** Always explicitly define and merge standard defense-in-depth secure browser headers (such as `x-frame-options`, `x-xss-protection`, `x-content-type-options`, `x-download-options`, `x-permitted-cross-domain-policies`, and `referrer-policy`) in any custom headers map returned to browser clients, to ensure consistent and redundant security protections.
