## 2026-07-24 - Bandit CVE-2026-65623 WebSockets Reassembly CPU Exhaustion
**Vulnerability:** In Bandit < 1.12.1, reassembling fragmented WebSocket continuation frames has quadratic O(n^2) computational complexity. This was caused by calling `IO.iodata_length/1` on the growing accumulated buffer on every incoming frame in `oversize_message?/2` to enforce the max fragmented message size cap. Because the cap does not bound frame count, an unauthenticated client sending tens of thousands of 1-byte continuation frames can completely starve BEAM schedulers, causing a Denial of Service (DoS) vulnerability.
**Learning:** Checking payload size on every iteration by traversing the entire nested list recursively creates a classic algorithm complexity bottleneck. Tracking fragment size incrementally with an integer state avoids traversing the list structure repeatedly.
**Prevention:** Ensure any dynamic length checks on lists/iolists within repetitive message-handling loops track cumulative counters incrementally rather than repeatedly calling traversal functions like `IO.iodata_length/1` or `length/1`. Keep core dependencies (like web servers/adapters) updated automatically to avoid known CVEs.
