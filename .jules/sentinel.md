## 2026-08-07 - [Phoenix Dynamic Security Headers Overriding]
**Vulnerability:** Default secure browser headers (such as `x-frame-options`, `x-xss-protection`, etc.) were completely stripped/overridden when invoking `Phoenix.Controller.put_secure_browser_headers/2` with custom map dynamic security headers (e.g., Content Security Policy). This leaves the application vulnerable to click-jacking, content sniffing, and other standard browser attacks on routes where those protections were bypassed.
**Learning:** In Phoenix, passing a custom headers map to `put_secure_browser_headers/2` can completely bypass default browser security protections because `put_secure_defaults` skips adding standard default headers if custom ones (like dynamic CSP) are processed or if custom maps bypass/replace default header structures rather than merging. Specifically, returning only a `%{"content-security-policy" => ...}` map from custom security modules and feeding that to `put_secure_browser_headers/2` strips other default headers like `x-frame-options`.
**Prevention:** Explicitly merge and output standard secure browser headers alongside any dynamic Content Security Policy in custom security header helpers to ensure defense-in-depth protections are not stripped.
