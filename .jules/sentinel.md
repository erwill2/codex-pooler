## 2026-08-04 - Overriding Secure Browser Headers in Phoenix
**Vulnerability:** Custom helper functions that set Content Security Policy (CSP) headers can completely override standard secure browser headers (such as `x-frame-options`, `x-content-type-options`, etc.) in Phoenix if they are not explicitly merged. This strips default browser protections, exposing the application to clickjacking, MIME-sniffing, and other client-side attacks.
**Learning:** Phoenix's `put_secure_browser_headers/2` allows passing a custom map of headers, which merges with the defaults. However, when writing custom wrapper plugs or helper functions that return custom headers, developers can mistakenly return *only* the content-security-policy header, effectively overriding and stripping out the default secure browser headers from the final connection if they are not explicitly included or merged.
**Prevention:** Ensure that any custom helper or plug responsible for generating secure headers explicitly defines and merges all recommended standard browser security headers (such as `x-frame-options`, `x-xss-protection`, `x-content-type-options`, `x-download-options`, `x-permitted-cross-domain-policies`, and `referrer-policy`) alongside dynamic headers.
