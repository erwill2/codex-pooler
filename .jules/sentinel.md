## 2026-07-20 - Prevent DoS via Unsafe Dynamic Atom Generation
**Vulnerability:** Unsafe dynamic string-to-atom conversion via `String.to_atom` and string interpolation `:"#{key}_iso"` within form processing, evaluation helpers, and settings maps. This allows potential attackers to exhaust the Erlang VM atom table (which has a hard limit and is not garbage-collected), leading to BEAM crash and Denial of Service (DoS).
**Learning:** Elixir developers often use `String.to_atom/1` for convenience when mapping key prefixes, lookup parameters, or nested settings maps. These patterns bypass compile-time safety guarantees, leaving the system vulnerable to memory exhaustion from untrusted dynamic strings.
**Prevention:** Utilize explicit case/pattern matching on known compiled-in strings to map them directly to predefined compile-time atoms. When mapping arbitrary keys inside generic helper structures, leverage `String.to_existing_atom/1` inside a `try/rescue` block to handle missing atoms gracefully without exposing a DoS surface.
