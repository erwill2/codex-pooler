## 2026-07-18 - Case-Insensitive String Checks in Hot Paths
**Learning:** For case-insensitive plan matching or general substring checks in hot paths, converting the string with `String.downcase/1` and checking substring matches using `String.contains?/2` is significantly faster (over 5.5x speedup) than executing dynamic regular expressions with `=~ ~r/.../i`. Furthermore, when optimizing case-insensitive multi-substring matching with `String.contains?/2`, checking a list of substrings (e.g., `String.contains?(s, ["a", "b"])`) is substantially slower than using explicit `or` conditions (e.g., `String.contains?(s, "a") or String.contains?(s, "b")`) because Elixir dynamically compiles list patterns at runtime.
**Action:** Always replace dynamic regex string matching inside candidate selection, routing, and accounting hot paths with `String.downcase/1` and explicit `or` pattern `String.contains?/2` checks.
